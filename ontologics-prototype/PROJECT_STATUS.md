## v2.2 후속 목록 개선의 기준 — 보존 기록

이미지 보완 v2.1과 이번 고밀도 목록 개선은 별도 작업이다. 후속 작업 전, 전달 v2.1 ZIP과 실행 중인 Downloads 사본 및 기준 작업폴더의 소스·테스트·자산·문서·주요 메타파일 91개를 읽기 전용 해시로 비교했고 모두 일치했다. 비교 대상에서 사용자 변경이나 누락은 발견되지 않았다. 기존 이미지 ID·원본 BOM·업무 수량·권한·승인 규칙을 후속 목록 표시 때문에 변경하지 않는다.

- 운영 홈의 `WorkQueueTable`은 기존 업무 5개를 고밀도 행으로 표시한다. 업무 수량은 필요한 EA·검토 건수·잔여 납품 약속·조사 대상 대수로 의미와 단위를 함께 표시하고 합산하지 않는다.
- `ConfigurationTable`은 모델 7종에 대한 등록 스냅샷 5개와 미확보 모델 3개를 8행으로 비교한다. BOM 행 수는 생산 수량이 아니다. 구성별 수요·필요일·실제 담당 근거가 없는 값을 생성하지 않는다.
- 홈 비교 목록과 객체 탐색 구성 목록의 사진은 기존 공통 미디어 확대/출처를 열고, 이름은 객체 상세·관계를 연다. 다음 조치만 해당 업무로 이동한다. 행 선택은 동일 객체를 Inspector/AI 맥락에 전달하며 자체 승인·예약·AI 호출을 실행하지 않는다.
- 두 비교 목록은 검색·정렬·열 표시·페이지 크기/위치·체크 선택을 계정/회사 범위에 저장한다. 선택 객체도 복원하며 필터에 가려진 체크와 현재 AI 대상을 구별해 유지한다. 사진 확대와 기준 상세를 열고 닫아도 목록 맥락을 유지한다. 필터로 표시할 결과가 줄면 존재하는 페이지로 보정한다.
- 홈의 구매 IM-0008과 납품회차는 제품 구성 연결을 추정하지 않는다. PoE L1의 자재 상태도 PART-TPS 대표 품목으로 제한한다. 검토 요청·승인 미반영·반영 완료와 원본 미등록·미확인은 구별한다.
- 구매·생산·납품·승인·BOM·이력 표의 수량과 업무 의미는 그대로 유지한다. 기존 전체 요구사항의 미구현/미연결 범위는 아래와 대응표에 남긴다. 후속 검증 결과는 [VALIDATION.md](docs/VALIDATION.md)를 따른다.


## v2.3 구매·생산·납품·검토 목록 확장

v2.2의 운영 홈/구성 표 패턴을 기존 업무 목록으로 확장했다. 업무 원장·객체 ID·이미지 자산·공개 포트·권한·승인 정책을 바꾸지 않으며, 화면 입력·검토 모달과 기존 ActionPort 실행 경로를 유지한다.

| 업무 / 구현 | 이번 목록 범위 | 수량·대상·상태 보존 |
|---|---|---|
| `PURCHASE / purchase-tables.tsx` | 구매 요청, 견적 조건 비교, 내부 발주, 공급 확인 | 요청량 ≠ MOQ/배수 계산 주문량 ≠ 확정 내부 주문량 ≠ 회신 누계/이번 회신량. 공급 확인은 재고가 아니며 미확인 운송비는 0원이 아님 |
| `UI07 / production-tables.tsx` | 생산 수요·자재 준비, 자재 소요, 반영된 자재 부분 입고·검사 | 제품 수요 대수와 대표 부품 개수 분리. 예약 ≠ 소비. 계획 미확보 ≠ 비교 부족. 입고 = 합격 + 불합격 + 대기, 실제 품목/로트 연결 미확인 보존 |
| `UI08 / production-tables.tsx` | 생산·완성품 입고, 회차 수량, 출하, 부분 도착, 전후 비교 | 정상/불량/대기·입고는 누계, 출하/도착 행은 사건 수량. 창고·운송·도착과 누계를 중복 합산하지 않으며 잔여 약속은 추가 생산량이 아님 |
| `UI05 / reviews.tsx` | 등록·정정 검토 목록, 검토·반영 이력 | 종류별 수량 의미·단위, 작성/승인자, 초안/기준/현재 버전 구분. 초안 수량을 실적으로 집계하지 않음. 목록 선택은 승인·반영이 아님 |

공통 `WorkflowTable`은 검색·정렬·열 표시·체크·페이지/크기와 활성 행을 회사/계정 범위로 보존한다. 구매 탭·비교안, 생산/납품 보기, 검토 상태 필터도 보기 상태로 취급한다. 사진은 확대·출처, 객체 칩은 상세·관계, 다음 조치는 기존 입력/검토 경로로 연결한다. 사진이나 행 선택 자체로 Agent 호출·승인·원장 쓰기를 실행하지 않는다. 연결된 객체가 없는 행은 이전 AI 대상과 새 검토 초안을 임의 결합하지 않는다.

IM-0008의 제품/구성, 입고의 품목·로트, 납품회차/출하의 제품·개별 보드 연결은 추정하지 않는다. 생산의 설계 구성 사진은 실제 생산 보드의 사진이 아니다. 실제 담당 배정이 없으면 작성/승인자와 구분해 미등록으로 표시한다. 구조화 객체·버전이 없는 감사 이력은 원문을 보존하고 이름을 근거로 관계를 만들지 않는다.

**기한 불일치 미결:** 기존 계획/이행 화면 요청 기한 `09.25 18:00 KST`와 `ROUND-01` 객체의 `09.30`이 서로 다르다. 두 값을 표시하고 미확인으로 유지했으며 약속·지연 판정·조건부 전망을 임의 변경하지 않았다. 통합 단계에서 원문 요청 기한과 회차 약속일을 대조한 뒤 각 의미와 우선 근거를 확정하는 것을 권고한다.

v2.1 이미지 보완, v2.2 홈 목록과 이번 확장은 별도 기록이다. 검증·캡처는 별도 브라우저 컨텍스트의 합성 자료를 사용하며 실제 운영 실적을 추가한 것이 아니다. 실제 실행 결과·캡처·미검증 항목은 [VALIDATION.md](docs/VALIDATION.md)에 구분해 기록한다. 아래 미구현/미연결 범위는 그대로 남긴다.

사진 확대·출처와 객체 이름 상세·관계를 구분한다. 행/체크는 명시 객체만 현재 AI 맥락에 연결하며 조회·정렬·사진·선택이 LLM 호출이나 원장 쓰기를 실행하지 않는다. 검색·정렬·열·페이지·체크와 보기 탭은 기존 회사/계정 범위에서 보존한다. 자재 이력·시험 요청 문서의 본문 이름으로 객체를 추정하지 않는다. 사진은 품목/보드 식별 참고이며 실제 장착·검사·결함 근거가 아니다.

조사 결과를 선택해도 사용자가 편집 중인 시점/기간/제외 조건을 덮어쓰지 않는다. ‘이 조회 조건 적용’만 저장 조건을 현재 입력으로 복사한다. 목록의 조회 버전과 AI의 최신 데이터 버전은 별도로 표시하며, 과거 스냅샷 데이터 자체를 복원하거나 같은 조건이 아닌 결과를 전후 비교 완료로 취급하지 않는다.

품질의 접수 대상은 `claimRecord`를 기준으로 표시한다. 현재 폼 입력이 다르면 기존 신고 원문을 바꾸지 않으며, 입력/접수 대상 불일치나 접수 대상 미등록 상태에서 가상 시험 예시 연결을 비활성화한다. 이는 기존 명령·승인 정책을 바꾸지 않는 UI 대상 확인이다. 실서버의 의뢰·시료·결과 대상 검증은 미연결 요구로 남는다. 신고 대상 1대·결과 행 1대를 불량 수량으로 세지 않고 미검사·전체 영향 미확인을 0/정상으로 처리하지 않는다. X/Y는 실제 제품 구성이 없는 별도 수량 예시다.

소비·반납·장착/제거·시험 사실 등록과 실서버 통합은 이번 목록 변경으로 완료되지 않는다. 기존 미구현 요구와 다음 절의 한계는 유지한다. 실제 검사·캡처·미검증 결과는 [VALIDATION.md](docs/VALIDATION.md)에서 이전 버전과 구분한다.

**제품 등록 미결:** 기존 원본 접수는 대표4개 해시를 식별하지만 등록 명령은 L1 ODS/PDF 근거를 고정 참조한다. 접수 해시와 이 등록 근거가 다르면 확인 안내를 표시하며 기존 명령/승인 정책은 임의 변경하지 않는다. 범용 등록을 연결할 때 원본·대상 구성·매핑·sourceHash의 일관된 계약과 서버 검증을 확정하는 것을 권고한다. 원본 목록의 개정 탐색이나 BOM 행 선택이 접수 대상·매핑 입력을 바꾸지는 않는다.

저장 업무 문서는 구조화된 대상·작성자·승인 버전·고유 문서 ID가 없으므로 원문 조합과 중복 순번의 표시용 ID만 사용한다. 본문의 U104·품목 이름·수량을 객체 관계나 승인 사실로 승격하지 않는다. 근거 목록의 사진은 해당 근거를 명시 참조하는 허용 객체의 대표 외형이고, 전체 참조 목록을 별도로 열 수 있다.

범용 OCR/매핑·새 보드의 구성 관계·일반 로트/장착 등록·문서 원장의 서버 연결은 부분/미연결로 유지한다. 실제 검사 수치·캡처·미검증 항목은 [VALIDATION.md](docs/VALIDATION.md)에서 이번 v2.5와 이전 기록을 구분한다.

## v2.6 후속 — 변경 영향·연결 보기

제품·BOM 등록(UI02), BOM/입고 검토 모달(UI05), 생산·자재 계획(UI07)에 `ChangeImpactPanel`을 연결했다. 패널을 열 때의 조회값·현재 반영상태·선택 초안의 반영 가정을 나란히 보여준다. 승인 자체는 현재 원장 수량을 바꾸지 않으며, 실제 ActionPort 반영 후에 현재 상태를 갱신한다. 이미 반영한 입고 후보를 다시 더하지 않고 기준 버전이 달라진 초안은 예측 대신 재검토 안내를 표시한다.

입고의 격리 가정 입력으로 도착50/합격40/불합격5/대기5를 합격30/대기15 등으로 바꿔 다음 확인 안내를 비교할 수 있다. 계산은 기존 `validate`, `receive`, `materialQuantities`를 사용하며 실제 초안·원장·예약·할당·Agent 요청을 변경하지 않는다. 가정이 실제 Alice 수정 내용으로 저장되거나 Bob에게 원격 전달되는 기능은 아니다.

기존 관계 그래프에서 `CFG-POE-L1` 로컬 등록 상태와 `PART-TPS` 계획 미확보 속성은 현재 객체 조회값을 사용한다. 제품은 구성 중심, 자재는 품목 중심으로 기존 설계/매핑 관계를 탐색한다. 관계 ID·방향·근거와 원본 BOM은 보존하며 RDF 트리플 생성·운영 투영 완료로 표현하지 않는다. 입고 후보와 LOT-L07은 근거 없는 실물 연결을 만들지 않는다.

- 구현: 같은 세션에서 상태 변화에 따른 조회·가정 재계산, 정확 승인/반영 구분, 객체·근거 탐색, 오래된 기준/불일치 수량/중복 가산 방지 표시.
- 미연결: Alice/Bob의 다중 사용자 동시 편집, 수정 초안 계보/대체 관계, 수정으로 인한 이전 승인 취소 정책, 변경 이벤트 구독, 실 Agent 자동 재추천, 서버 RDF/OWL 투영과 다른 서버의 그래프 갱신.
- 권고: Bob이 검토한 초안 ID·버전·해시를 고정하고 새 버전 알림과 차이를 별도 표시한다. 원장 반영과 그래프 투영 완료의 버전을 분리한다. 공개 계약 변경은 확정하지 않고 DOCUMENT_AMENDMENTS.md에 필요한 협의 항목을 남겼다.

현재 사용자 브라우저의 업무 기록을 초기화하거나 시연용 승인·입고·할당을 대신 작성하지 않았다. 별도 검사 브라우저에서 검증하며 기존 v2.0과 공급사 카드 변경은 유지한다.

## 2026-11-05 별도 그래프 서버 후속 — 로컬 읽기 복제

앞선 ‘변경 영향·연결 보기’ 기록에서 미연결이었던 **다른 서버의 그래프 조회**를 로컬 개발 범위로 추가한다. 기존 5174의 v2.0과 5175의 v2.6 업무 화면을 유지하고, 그래프 화면은 별도 Node/Vite 프로세스의 `http://127.0.0.1:5176/`에서 제공한다. 처음에는 업무 화면의 **그래프 서버 연결**을 명시적으로 누른다. 연결 후 저장된 업무 상태·검토 상태가 바뀌면 같은 세션의 읽기 스냅샷을 갱신한다. 사용자 브라우저의 기존 업무 데이터는 초기화하지 않는다.

| 구분 | 이번 구현 범위 | 완료로 해석하면 안 되는 범위 |
|---|---|---|
| 업무 기록 | 기존 브라우저 Mock와 ActionPort를 유지. `ledgerVersion`은 해당 로컬 업무 버전 | 서버 원장·기업 DB의 영속 반영 |
| 그래프 갱신 | 수신 `sequence`, 완료 순번, 업무 버전, 그래프 완료 버전과 대기/완료/실패를 별도로 표시. 약400ms 투영 지연은 개발 시연용이며 조회 화면은 약700ms마다 상태를 확인 | 실제 현장 이벤트 실시간 수신, RDF/OWL/SHACL 투영 |

기본 fixture의202개 객체·191개 관계는 같은 식별자로 유지한다. 추가 등록한 보드는 기존 등록 ID로 포함할 수 있지만 미확인 구성·장착 관계를 생성하지 않는다. 입고에 품목/로트 ID가 없으므로 입고→LOT-L07 선을 만들지 않으며, RES-01은 다른 계획20EA 예약 그대로다. 관계를 새로 생성한 것과 기존 객체 속성의 새 조회 버전을 구별한다.

상태: **로컬 연결 구현·브라우저 검증 완료 / 운영 연결은 미연결**. 이번에 단위72개·서버6개·브라우저21개와 실주소 후속3개를 확인했다. 서버 중단·지연·권한 범위·순서 역전·중복·계정 전환과 실제 화면 검사의 수행 결과는 [VALIDATION.md](docs/VALIDATION.md)의 ‘별도 그래프 서버’ 기록만을 따른다. 앞선 검사 수치를 이번 검사 결과로 사용하지 않는다. 운영 배포·실 인증·영속 그래프·서버 원장 이벤트·여러 사용자 동시 작성·실 LLM 재추천은 미연결 요구로 유지한다.

개발 연결의 읽기 토큰은 그래프 창 세션 저장소에 보관하고, 서버 연결은 메모리 전용/2시간 만료다. 업무 창의 연결 확인 전에는 객체를 표시하지 않는다. 명시 연결 이후 저장 상태만 게시하며, 미저장 가정 입력·사진·선택·테마는 게시나 업무 쓰기를 발생시키지 않는다.
