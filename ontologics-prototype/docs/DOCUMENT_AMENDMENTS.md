# 기존 세 문서 수정안

## 2026-11-06 최신 수정안 — 실제 BOM 5개 등록·ABox 반영

사용자는 나머지 실제 BOM도 기존 승인 규칙으로 등록하도록 요청했다. 아래 v1.7 정합화 절의 L1 전용 등록 제한은 당시 기록으로 남기고, **확보된 5개 스냅샷의 브라우저 Mock 등록**에 한해 다음 변경으로 대체한다. 새로운 승인 정책·ERP DB·Agent 백엔드·운영 API를 확정하는 변경이 아니다.

| 반영 문서 / 유지 ID | 추가·갱신할 내용 | 업무 의미와 구현 경계 |
|---|---|---|
| 01 공통 / REG-01~04, CM01, AT01 | 원본 확보·구조 검토·초안·검토 요청·승인·반영을 각 상태로 유지하고 L/L1·ISO N·EVB C·GATEWAY I를 동일 흐름으로 지원 | 원문 미검수 보존 승인은 실장·단위·정확 품번 검증 완료가 아님. 미확인 항목 수를 새 승인 차단 정책으로 사용하지 않음 |
| 01 공통 / RV01~03, AT03, T15-02/04 | 기존 작성자/승인자 분리, Bob 승인 역할, 정확 초안/기준 버전/해시, 회사 범위, 같은 요청 멱등성 유지 | 승인만으로 원장·수량·등록 근거 그래프가 바뀌지 않음. 오래된 기준·변조·대상/원본 불일치는 거부 |

| 03 개발 / 이전 데이터·복구 | 구형 L1 초안은 정확 근거/해시 확인 시 원래 내용 그대로 처리. 근거 부족은 새 초안 안내. boolean-only 기록은 상세 근거 미확인으로 유지 | 이전 승인 해시를 재작성하거나 다른 구성으로 재해석하지 않음. 고정 원본의 중복 등록은 기존 정확 반영 기록/동일 요청 조회로 안내 |

변경 이유는 화면마다 다른 구성이나 L1 승인 상태가 섞이는 것을 막고, 사용자가 정확 버전 반영으로 실제 바뀐 등록 근거를 읽을 수 있게 하는 데 있다. 재고·생산·납품의 양과 단위, 사내 품목 매핑, 실제 장착·회로 검증의 기존 미구현 요구는 유지한다. 최신 검사와 미검증은 [VALIDATION.md](VALIDATION.md)의 같은 제목 절을 따른다.


기준일: 2026-11-06 / v2.6. 이 파일은 원본 v1.5를 덮어쓰지 않고 재설계 후 반영할 변경 제안을 기록한다. 현재 사용자의 명시적 요청이 첨부 문서 속 GPT/Codex 작업 지시와 MK-R2 고정 배치 조건에 우선한다. 기능·수량·시간·권한·승인·공개 계약의 업무 의미는 변경하지 않는다.

## 기존 프로토타입 문서에서 정정할 표현

기존 README/PROJECT_STATUS/REQUIREMENT_TRACEABILITY/DECISIONS는 이전 작업 기록이다. 최신 보고와 혼용하지 않도록 날짜와 범위를 유지하고 새 재설계 문서로 연결한다.

- `D05 부분 인수 채택 미결`, `부분 수량 차단`, `전량 도착만 허용`은 v1.5 이후 기준으로 사용할 수 없다. 이번 기준은 shipment별 복수 부분 arrival과 상한·중복 검증이다.
- D02 고정 job, D03 실물/완전성, D04 생산→입고→회차배분, D06 시험/구성별 응답 계약은 v1.5에서 개발 기준이 구체화되었다. 실제 코드/API 미연결과 정책 미채택을 구별한다.
- `UI01~UI09가 전체 화면 범위`라는 설명은 객체 탐색·구매·전체 지도·관리자 초안·운영 감사를 포함하도록 확장한다.
- `실제 원본 4개`는 파일 개수다. 모델 4종·전체 BOM 5스냅샷 확보와 동일하지 않다.
- 이전 원장의 도착20과 새 합성 스냅샷의 도착32는 서로 다른 데이터셋/시점일 수 있다. 한 스냅샷으로 섞지 않고 데이터 모드·버전을 표시한다.
- 기존 AT02의 2026-09월 시점/기간 fixture와 MK-R2의 10월 또는 11월 운영 홈 fixture는 별도다. 화면의 오늘 날짜로 사건 시각을 덮어쓰지 않는다.

위 수정안은 화면 표현과 연결을 바꾸며 새로운 업무 승인 정책, 실제 외부 송신, 현장 제어, 회계·세무·결제 범위를 추가하지 않는다.

## 최종 구현에 맞춘 추가 문구

- 공통 포트의 UNKNOWN 사례는 브라우저 재기동 후에도 원결과/미확인 키를 보존한다. 실제 서버 요청 대사는 별도 어댑터 책임이다.
- 미저장 입력 확인은 버리고 전환/취소로 제공한다. 모든 폼을 완전 복원한다고 표현하지 않는다.
- 실제 미확보 3모델과 실행용 합성 3모델은 구분한다. `TRACE-*` 출하 경로도 운영 100대 계약 원장과 별도 fixture다.
- PNL-10/21/24는 구조화 검토 문서 입력을 추가한다. 문서 저장은 사실 반영·시험 판정·현장 실행이 아니며 해당 도구 연결 전에는 이 경계를 유지한다.

## v2.2 이미지 보완 이후의 고밀도 목록 개선 — 보존 기록

이미지 보완 v2.1의 자산 추가와 이번 목록 재배치는 별도 변경이다. 새 사양 파일을 만들지 않고 이 기존 수정안, 요구사항 대응표, 구현·연결 상태와 검증 기록에 반영한다. 원본 세 문서와 읽기 전용 참조 자료는 변경하지 않는다.

후속 작업 전 전달 ZIP, 기준 작업폴더, Downloads 실행 사본을 비교했다. 소스·테스트·자산·문서·주요 메타파일 91개의 해시가 일치했으며 비교 대상에서 사용자 변경과 누락은 발견되지 않았다. 새 예시 이미지의 원본 파일은 이 조사에서 확보되지 않았으므로 해당 이미지를 직접 검수했다고 기록하지 않는다.

실시간 협업의 권고 흐름은 다음과 같다. Alice가 저장한 변경 후보와 Bob이 실제 검토한 초안 ID·버전·해시를 각각 보존한다. 변경 알림을 받으면 Bob에게 차이와 새 검토 대상을 보여주되, 보고 있던 승인 대상을 다른 내용으로 조용히 교체하지 않는다. 승인 요청은 서버가 검토 토큰과 회사/권한·현재 기준을 다시 확인해야 한다. 새 수정 초안이 기존 초안을 대체하는지, 이전 승인을 취소할지는 기존 정책과 초안 계보 계약을 먼저 확정해야 하며 이번 화면 작업에서 임의 정책을 추가하지 않는다.

원장 반영 이벤트가 발생하면 연결된 조회/계산 결과를 무효화하고 새 버전으로 조회한다. RDF/그래프 투영은 별도 완료 이벤트·투영 버전·실패/재시도 상태를 보여준다. 화면이 다른 서버에 있어도 같은 객체 ID·회사 범위·초안/원장/투영 버전으로 조회해야 한다. 전송 방식과 엔드포인트, 이벤트 스키마는 미확정이며 실제 서비스 계약으로 보고하지 않는다. 이벤트 수신만으로 다른 사용자의 작성 입력을 자동 저장하거나 기존 요청을 반복하지 않는다.

현재 `draft.revise`는 같은 내용을 새 ID/버전으로 복사하며, 수정 입력·초안 대체 관계·동시 작성 동기화는 미구현이다. 시연 가정 입력을 이 기능의 완료로 간주하지 않는다. 기존 단일 세션 계정 전환과 다른 탭의 계정 변경 시 잠금 규칙도 유지한다.
