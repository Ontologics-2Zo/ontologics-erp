2026-11-06 실제 BOM v1.7 정합화·ABox / 클래스 탐색·BOM 부품 구성도 / BOM 정합성·수급 현황 보완 / 2026-11-05 온톨로지·운영·요구 목록 v2.6 / 제품·보드 등록·문서 목록 v2.5 / 자재·재고·조사·품질 목록 v2.4 / 구매·생산·납품·검토 목록 v2.3 / 고밀도 목록 v2.2 / 이미지 보완 v2.1 / 2026-11-04 재설계 구현. 기존 React 19 / TypeScript / Vite 프로젝트와 승인·수량 계산을 유지하고 객체 탐색, 자재·구매, 온톨로지 지도와 격리된 관리자 초안 편집을 추가했다. 사용자 요청이 첨부 문서의 MK-R2 고정 배치·동선 조건을 대체한다. 원본 `sources/`와 첨부 세 문서는 수정하지 않았다.

이 결과물은 **실행 가능한 로컬 프론트엔드**다. 브라우저 Mock을 통해 실제 입력·초안·별도 승인·정확 버전 반영·부분 수량·요청 대사를 수행한다. 실제 인증/원장/DB/Agent/ERP는 연결되지 않았다. 운영 배포나 실제 발주·메일·설비 제어는 수행하지 않았다. 모든 전체 요구사항을 운영 수준으로 완료했다는 뜻은 아니다. [화면별 범위](PROJECT_STATUS.md)와 [상세 대응표](docs/REDESIGN_TRACEABILITY.md)에 미구현·부분·미검증 범위를 남겼다.

## 실행

`package.json`과 `package-lock.json`이 있는 이 폴더에서 다음 명령을 실행한다. 기존 v2.0 압축본은 한 단계 아래 `ontologics-prototype`로 이동해야 한다. 새 v2.6 소스 ZIP은 압축을 푼 폴더 바로 안에 두 파일을 둔다. 현재 비교 실행은 v2.0 `http://127.0.0.1:5174/`, 최신 v2.6 `http://127.0.0.1:5175/`, 별도 그래프 `http://127.0.0.1:5176/`다. 아래 명령은 최신 v2.6 폴더 기준이다.

```sh
npm ci
npm run dev -- --port 5175 --strictPort
```

다른 터미널에서 같은 폴더의 별도 그래프 서버를 실행한다.

```sh
npm run graph
```

업무 화면 상단 **그래프 서버 연결 → 별도 그래프 열기**를 누른다. 5176 주소를 직접 여는 것만으로 객체·집계가 노출되지는 않는다. 업무 창이 연결한 회사·세션과 객체 선택을 공유하고, 업무 창과 그래프 창을 나란히 둘 수 있다. 기존 v2.0은 원본 폴더에서 5174로 유지하며 별도 그래프 연결 대상이 아니다.

예시: Alice로 수요 확인·예약60·입고 검수 초안50/합격40/불합격5/대기5·검토 요청 → Bob으로 전환 → 그래프 연결/열기 → 검토함에서 승인 → 별도 반영 → 합격분30 할당. 승인만으로 합격 누계나 업무 버전이 바뀌지 않는다. 반영 후 그래프가40개를 받고, 할당 뒤 계획 미확보가40→10개가 된다. 회사·계정 전환 시 연결이 폐기되므로 새 계정에서 다시 연결한다.

별도 서버는 기존 브라우저 Mock 상태의 메모리 읽기 사본이다. 운영 DB/RDF 엔진·실제 사용자 동시 작성·실 LLM 재추천은 연결되지 않았다. 약400ms의 갱신 지연은 개발 시연용이고 화면은 약700ms마다 작은 상태 정보만 조회하고, 완료 순번이 바뀔 때만 전체 그래프 데이터를 받는다. 같은 응답은 이미지·확대창·표를 다시 만들지 않는다. 서버 재시작 또는 연결 후2시간이 지나면 다시 연결해야 한다. 그래프 장애가 발생해도 업무 기록을 되돌리거나 승인/반영 요청을 반복하지 않는다. 상단 오류를 확인하고 **같은 게시 재확인**, 만료 시 **연결 해제 → 그래프 서버 연결**을 사용한다. 이 임시 연결은 운영 인증이 아니다.

`npm run graph`는 Vite를 사용하는 로컬 개발 서버다. `dist/graph.html`만 별도 호스팅해서는 조회 서비스가 제공되지 않는다. 운영 배포/인증/API 계약은 기존 문서의 후속 통합 항목으로 남겨 둔다.

기존 `node_modules`와 lock 파일을 사용했다. 이번 작업에서 새 패키지를 추가하지 않았으며 `npm ci` 재설치는 수행하지 않았다. Node.js 22.12 이상이 적합하다.

```sh
npm run build
npm test
npm run test:graph
ONTO_PREVIEW_URL=http://127.0.0.1:5175 npm run test:e2e
```

`build`는 TypeScript 검사 후 정적 `dist/`를 만든다. 브라우저 시험은 설치된 Google Chrome과 실행 중인 로컬 서버를 사용한다. 다른 포트는 `ONTO_PREVIEW_URL=http://127.0.0.1:포트 npm run test:e2e`로 지정한다. 테스트는 별도 브라우저 컨텍스트에서 실행되며 사용자 브라우저 자료를 삭제하지 않는다.

개발 계정은 localhost / 127.0.0.1 / ::1에서만 사용한다. 다른 호스트에서는 작업 화면을 차단한다. 이는 서버 인증을 대체하는 보안 장치가 아니다. 실제 서비스에는 검증된 IdentityPort와 서버 권한 검사를 연결해야 한다.

## 대표 동선

1. **제품·BOM 등록** → 포함된 L1 원본 → 3단계 **BOM·정합성 검토**에서 원본74행·128참조 표기, 명칭 차이·미확인·근거·관계 확인. **부품 구성도**에서 기존 사진·참조 위치·수량·패키지를6행씩 탐색 → 등록 검토 단계 → 등록 초안 → 검토 요청. 계정을 Bob으로 전환하고 검토함에서 정확 버전 승인 → 별도 반영 → 재조회.
2. **자재·대체 검토 → 수급 현황** → 현재 계산 가능한1품목의 비교 부족·계획 확보·합격 미할당을 확인 → 원품/범위 승인 대체품/미승인 후보 비교 → 생산 계획에서 수요 확인·예약 → 입고·검사 초안 승인 → 합격분 할당. 비교 가용 부족과 아직 예약·할당하지 않은 수요를 구분한다.
3. **제품·객체 탐색 → 관계 탐색** → 실제 장착 이력 / 확인된 출하 추적. `TRACE-*` 경로는 별도 합성 예시다. L07/U104 조사에서는 미확인을 유지하고 보완 승인 후 A/B 동일 조건을 비교한다.
4. **구매·공급 관리** → 구매 요청 → MOQ/배수/미확인 운송비 비교 → 내부 발주 초안·승인 → 공급 확인 초안·승인. 외부 송신이나 입고를 자동 생성하지 않는다.
5. **생산 실적·납품** → 정상/불량/대기 → 완성품 입고 → 명시 배정 → 분할 출하 → 부분 도착. 예: 출하 20+15 / 도착 20+12이면 운송 중 3, 도착 32, 잔여 약속 68대다.
6. **온톨로지 지도 → 클래스·관계 탐색** → 도메인별6개 기존 클래스·5개 관계 → **해당 유형 객체 보기** → 사진 확대/객체 상세. 클래스 선택은 기존 업무 AI 대상을 유지하며 객체 선택부터 바뀐다. 기존 **업무 전체 지도**와 Bob의 **TBox · 관리자 초안**도 그대로 제공한다. 클래스·관계·제약, 배치 변경과 의미 변경, 모의 검증과 운영 적용을 구분한다. 운영 적용은 비활성화되어 있다.

구매 요청·견적·발주·공급 확인, 생산 수요·자재·입고, 생산 작업·납품회차·출하·도착, 검토·승인 이력에 같은 고밀도 표 패턴을 적용했다. 업무 수량과 초안·승인·반영은 각각의 의미를 유지하며, 명시되지 않은 제품/품목 관계와 날짜 불일치는 미확인으로 남긴다.

v2.4에서는 자재 비교·로트 재고·예약·원문 이력4표, 조사 결과·장착/제거 근거2표, 접수·영향·의뢰·결과·재생산 예시5표로 확장했다. 저장한 조사 조건과 현재 AI 기준, 접수 대상과 편집 입력을 구별하고 같은 사진/객체/선택 규칙을 적용한다. v2.4 당시 검사 결과는 빌드 성공·단위69개·브라우저37개 통과이며, 이전 검사 기록은 별도 보존했다.

v2.5에서는 제품 원본·개정별 BOM·등록 입력 요약, 개별 보드·등록 초안, 문서·근거와 저장 문서의7개 표 패턴을 적용했다. 원문74행·등록 식별자·자유 문서의 의미를 유지하며, 명시 관계가 없는 신규 보드와 문서는 미확인으로 표시한다. 사진 확대·객체 상세·AI 선택을 구별하고 정확한 보드 등록 초안으로 검토를 이어갈 수 있다. v2.5 당시 검사는 빌드·단위69개·브라우저43개 통과이며 이전 실행 기록은 별도 보존한다.

v2.6에서는 온톨로지 객체·정책·버전3표, 운영 감사·수량·연결 상태·공통 포트4표, 요구·결정·수용 정의·연동 경계4표로 확장했다. 업무 객체가 아닌 참조 목록은 기존 객체와 AI 대상을 유지하며, 명시 객체 목록에서만 사진·상세·AI를 연결한다. 지도·TBox 편집·모의 검증·저장·검토와 운영 적용 제한은 그대로 유지한다. 고밀도 목록 v2.6 당시 검사는 빌드·단위69개·브라우저49개 통과이며 후속 검사와 구분한다.

2026-11-06 후속에서는 첨부 예시의 사진·관계·검토표 구성을 기존 기능에 적용했다. BOM 정합성은 실제 L/L1 원문 표기 검사이며 회로도·데이터시트 대조는 미연결이다. 자재 수급 현황은 전체74행 중 U2/PART-TPS 1품목의 기존 합성 계산만 제공한다. 공급·견적·필요일을 추정하지 않고 기존 승인/할당·별도 그래프·미디어 자산을 유지한다. 이번 검사 결과와 캡처는 [VALIDATION](docs/VALIDATION.md)의 2026-11-06 절을 확인한다.

이번 추가 후속의 클래스 탭은 공유 기본 정의를 읽고 관리자 초안 저장과 분리한다. 업무 객체는 QueryPort의 회사 허용 결과에서 정확한 UI 유형으로 연결하며 RDF 소속을 추론하지 않는다. BOM 구성도는 GraphPort의 실제 구성→원문 품목 관계만 표시한다. 참조 기호 분산/원문 행 순은 표시 순서이고, 사진과 관계는 실물 좌표·장착·호환성 증거가 아니다. 기존32개 미디어 자산을 그대로 사용했다. 이번 추가 검사·캡처는 [VALIDATION](docs/VALIDATION.md)의 최상단 기록에 있다.

운영 홈은 업무5행과 제품·구성8행의 고밀도 비교 표다. 사진은 확대/출처, 이름은 상세/관계, 다음 조치는 해당 업무로 연결한다. 두 표의 필터·정렬·열·페이지·체크와 선택 객체는 회사/계정별로 복원하며, 선택만으로 AI 호출이나 원장 쓰기를 실행하지 않는다.

상단의 테마와 행 밀도는 저장된다. 표의 객체 칩을 선택하면 Inspector가 열린다. 우측의 업무 AI/객체 정보는 같은 자리에서 전환되며 동시에 중앙을 좁히지 않는다. AI 요청에는 선택 ID·회사·구성·시점/기간·버전·선택 초안 버전이 포함된다. 이전 대상/계정의 늦은 응답은 폐기한다.

## 개발 계정과 저장

- Alice: 회사 A의 작성. 승인 권한 없음.
- Bob: 회사 A의 검토·관리 UI 시뮬레이션. 자기 승인 금지.
- Viewer: 회사 A 조회 전용.
- Guest B: 회사 B. 회사 A의 객체·통계·사진·문서·대화 비노출.

전환은 명시적으로 확인하며 미저장 입력이 있으면 버리고 전환하거나 취소한다. 폼 임시값은 계정별로 분리된다. 업무 초안과 승인 이력은 회사 범위의 공동 로컬 기록으로 남는다. 진행 중/결과 미확인 쓰기가 있으면 전환하지 않는다. 다른 탭의 계정 전환 신호를 받으면 이전 표시를 닫고 재확인을 요구한다. 다중 탭 동시 쓰기·DB 트랜잭션은 지원하지 않는다.

기존 `ontologics-v1` 상태를 보존한다. `actionReceipts`와 미확인 요청 키도 로컬 상태에 저장하여 새로고침 후 같은 요청 결과를 확인한다. 이 프론트엔드의 수량·권한 검사는 실제 서버 검증을 대신하지 않는다.

- 실제 목표 중 미확보: ESP32-POE-ISO, ESP32-EVB, ESP32-GATEWAY. 미확보 객체로 노출한다. 합성 3종이 실제 자료 확보 목표를 대체하지 않는다.
- 이미지 보완 v2.1: 모델 7개에 제조사 참고 사진 4개/AI 참고 3개, 품목 객체 174개에 AI 참고 172개/미등록 2개를 연결했다. 검수된 실물 사진·CAD는 0개다. AI 생성 배지·확대 설명·출처·개정 미검수·비근거 용도를 구분한다. 상세 집계: [이미지 감사 보고](docs/MEDIA_ASSET_AUDIT.md).
- 10만 객체는 프로젝트 목표다. 전체 집계는 `미집계`, 화면의 로컬 fixture 수는 실제 계산값으로 표시한다. 대규모 적재/부하 시험은 하지 않았다.

## 이미지 보완 v2.1

이미지 생성은 OpenAI 내장 도구로 사전 수행했다. 화면/hover에서는 저장 파일만 읽는다. `public/media/`의32개 파일과 `docs/MEDIA_GENERATION_PROMPTS.json`의28개 생성 프롬프트를 함께 전달한다. 홈·제품·BOM/재고·미리보기·대체품·온톨로지 객체 상세가 같은 매핑을 사용한다. 확대 시 출처, 개정 일치 상태, AI 안내와 비근거 용도를 표시한다. 정확한 실물 사진을 확보하면 업무 데이터 변경 없이 `mediaAssets/mediaBindings` 또는 검수된 `Entity.photo`로 교체한다.

빌드 및 단위59/브라우저24 검사 통과. 상세 검증은 [VALIDATION](docs/VALIDATION.md), 객체별 자산/수/미등록 사유는 [MEDIA_ASSET_AUDIT](docs/MEDIA_ASSET_AUDIT.md)에 있다.

## 실제 BOM v1.7 후속

실제4모델·5스냅샷(74/74/75/71/62행)을 제품 등록의 원본 선택기와 객체 탐색에서 확인합니다. 원문·정합성·부품 구성도는 같은 구성/행 ID를 사용합니다. 단위·실장·정확 MPN은 미확인입니다. 기존 독립 합성3스냅샷은 별도입니다.

업무 전체 지도는 ABox 객체를100개씩 조회합니다. 이름/ID 검색·유형·자료 필터를 사용하고, 행을 활성화하면 아래 속성/관계와 AI가 같은 객체를 공유합니다. 여러 체크는 일괄 선택이며 단일 활성 객체와 다릅니다. 부분 다운로드는 내보낸 객체 사이의 관계만 포함합니다.

원본 재현: `python3 scripts/import-actual-boms.py --input /path/to/ontologics_solo_docs_data_v1.7.zip --check`. 포함된 고정 데이터만 대상으로 하며 임의 업로드·OCR·제조 적합성 검증은 아닙니다. 새 CSV를 다른 모델의 L1 승인 명령으로 저장하지 않습니다. 기존 L1만 정확 원본 접수→초안→별도 승인→반영을 수행합니다.
