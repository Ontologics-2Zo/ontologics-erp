# ADR-0002 — 실제 BOM 출처 정합화와 ABox 현재 객체 조회

날짜: 2026-11-06 · 상태: 검토 요청 · 범위: v2.6 프론트엔드/Mock, 실제 ERP DB·Agent 구현 제외

## 문제와 입력

Git main `31437ef`의 반입 기준 이후 로컬에서 제품 정합성·수급 현황·클래스 탐색·부품 구성도 후속 작업이 진행되었다. 이번 브랜치는 그 최신 로컬 UI를 보존한 상태에서 v1.7 BOM 데이터를 연결한다. 따라서 PR에는 아직 Git에 없던 해당 공통 화면도 함께 포함한다. 프레임워크·lock·수량/승인 권위는 유지한다.

제공 `ontologics_solo_docs_data_v1.7.zip`은 실제4모델·5스냅샷의 전체 원문356행을 포함한다. ZIP SHA-256은 `314b731fb899378961cffccadab2d1b49bf8f0cec0c376f9b101af67c90c13dc`다. 제공 manifest53파일을 대조하고, BOM5개의 bytes/SHA-256/Git blob SHA-1 및 원문셀/행 locator를 확인했다. 기존 ODS/PDF4파일은 동일하다. 새 CSV3개는 ISO75/EVB71/Gateway62행이다. BOM 원문 확보 기준은2026-11-05이고 합성 운영 시각2026-09-20과 별개다.

## 선택과 이유

1. **공통 원문 어댑터**: 화면별 값을 복사하는 대신 `actual-boms.ts`와 검증된 `actual-bom-data.json`을 사용한다. 원문과 입력 정규화 후보를 오프라인 스크립트에서 대조해 생성하며, 이 JSON은 런타임에 필요한 추적 가능한 데이터다. 배포 빌드/시험 산출물과 다르다. 임의 파일 파서·OCR·백엔드는 만들지 않는다.
2. **행 기반 ID 보존**: 기존 L/L1 `BOM-/PART-POE-{revision}-{row}`와 MODEL ID를 유지한다. 새 CSV는 물리 line 기반 ID다. 이름·패키지·Ref**로 합치면 서로 다른 사용 위치와 빈 참조가 손실되므로 채택하지 않았다. CSV line2도 포함한다.
3. **미검수의 유지**: 원문 숫자합660은 조달/실장 수가 아니다. 356행의 단위·실장·MPN은 미확인이다. PoE WROOM/WROVER/RevJ 불일치, EVB 빈 위치·쉼표·Ref** 중복, NA/NS/Opened/Closed를 그대로 보존한다. 형식 검사 통과와 독립 검수/승인은 분리한다.
4. **새 구매 품목과 기존 기록 분리**: IM-0008(10uF/25V)을 실제 BOM 사양으로 덮어쓰면 과거 문서의 의미가 변한다. EVB C 원문행21/C18,C26에 연결한 `IM-EVB-C-C18-C26`을 새로 만들고,40대×원문2=80EA·가용0은 명시적 합성 가정으로 둔다. 기존 견적/요청/발주는 별도 범위에서 보존한다. 생산표는 PART-TPS 공통 계산값을 사용하며 미승인 후보를 재고0으로 바꾸지 않는다.
5. **등록 계약 유지**: 기존 ActionPort의 BOM 명령은 L1용이다. 새 모델을 선택한 채 그 명령을 보내는 대안은 대상/버전 혼입을 일으킨다. 새 모델의 읽기·검토·원문 접수만 연결하고 등록 저장은 미연결 사유와 함께 비활성화한다. L1도 정확한 L1 ODS 접수 해시일 때만 저장한다. 일반 구성 등록 명령은 별도 계약 검토 과제로 남긴다.
6. **현재 ABox 조회**: 기존 지도만 정적 seed를 읽어 런타임 보드와 현재 자재 속성이 빠졌다. 공통 QueryPort 조회로 통일한다. 100개씩 읽고 표를 점진 확장하며 전체 목표/검색/로드/표시/부분 결과를 분리한다. 다운로드는 내보낸 객체 양끝이 존재하는 관계만 포함한다. TBox6클래스/5관계와 관리자 초안은 그대로다. 10만 객체 전체 렌더링이나 RDF 추론을 추가하지 않는다.
7. **AI와 사건 범위**: 다른 모델에서 수량을 물으면 PoE100대 원장을 답하던 예시 응답을 객체 범위별로 나눈다. 원문 행은 원문 수량/미검수를, 합성 구매는 해당 가정을 설명한다. 다른 모델의 사건 이력·승인 플래그에 L1 상태를 대신 표시하지 않는다. 응답 지연 격리와 승인 우회 방지는 유지한다.

## 절충과 미완료

전356행의 공통 원문/출처를 함께 배포하므로 공통 번들 크기 경고가 있다. 현재 수백 객체 화면을 구현한 결과이며 실제10만 객체 성능을 입증하지 않는다. 대규모 서버 연결 시 Query/Graph 페이지 조회와 데이터 분할을 유지해야 한다. 실제 ERP DB, 품목 매핑 승인, 전체 BOM 소요, 실장 증거, 실 Agent, RDF/SHACL, 신규 모델 일반 승인·반영은 미연결이다. 독립 합성 IO/SENSE/PWR·추적·X/Y 재생산 예시는 실제 BOM과 별도로 유지한다.

기존 사용자 로컬 기록을 초기화하거나 구형 품목 ID를 마이그레이션하지 않는다. 이미지32파일을 유지하며 제조사 사진4장은 기존 Git 제외/로컬 복원 정책을 따른다. 원본 BOM의 상위 저작권·고지는 유지한다.

## 검증과 복구

최종 수행 명령·결과·중간 실패/보완·캡처 경로는 앱의 `docs/VALIDATION.md` 새 v1.7 절에 기록한다. 이전54/27개 등 기록을 이번 결과로 재사용하지 않는다. 검증용5177/5186/5189는 현재5175/5176과 분리했다. 개인 원본 ZIP·의존성·빌드·캡처·테스트 trace는 Git에서 제외하고 ZIP 산출물에 소스·이미지·보고를 제공한다.

PR은 별도 `feat/v17-bom-alignment`에서 검토하며 자동 병합하지 않는다. 취소는 PR을 닫고, 반영 후 복구는 revert PR로 한다. 로컬 최신 ZIP 교체 전 보관한 이전 ZIP과 사용자 저장 기록을 유지한다. 새 모델을 미확보 상태로 되돌리는 경우에도 이미 저장된 승인 원장이나 BOM ID를 재해석하지 않는다.

최종 확인: 단위96개·그래프6개 통과. 브라우저 전체실행68개 통과 후 환경 문제1개를 시험 코드만 수정해 별도 재검 통과했다(고유69항목 확인, 한 번의69통과 실행 아님). TypeScript/Vite 빌드 성공, 공통 청크702.89KB/gzip109.57KB 경고 유지. 원본 재현6파일·5해시, 기존 정책/자료/이미지40파일 불변도 확인했다. 상세 명령·실패 원인은 VALIDATION 새 절을 따른다.


## 2026-11-06 후속 결정: 확보한 5개 BOM의 Mock 등록과 ABox 근거 연결

사용자가 L1 이외 4개 실제 스냅샷도 같은 초안→검토 요청→승인→반영 흐름으로 이어 달라고 요청했다. 이 절은 앞선 L1 전용 등록 제한을 대체하며, 기존 원본 정합화와 출처 결정은 유지한다.

### 문제와 선택

기존 `bomApplied` 단일 boolean은 PoE L1만 설명할 수 있었다. 이를 모든 BOM에 공용으로 켜면 한 모델의 승인이 다른 모델의 승인으로 잘못 보인다. 구성별 고정 원본·제품·개정·행 수·원본 해시를 검증하는 `bom-registration.ts`와 구성별 `State.bomRegistrations` 기록을 선택했다. 기존 ActionPort 명령과 작성자/승인자 분리·Bob 권한·기준 버전·승인 해시·멱등성 검사는 유지한다. 실제 서버 API를 새로 합의하거나 DB/Agent를 구현하지 않았다.

승인 대상은 원문과 미검수 상태를 보존하는 등록안이다. 원문 정정이나 공학 검수 완료가 아니다. PoE L/L1의 WROOM 파일/시트 불일치, EVB 빈 위치·중복·NA/NS/Opened/Closed, 원문 수량·단위/실장/MPN 미확인을 그대로 유지한다. 수량 원장·사내 품목 매핑·생산 소요는 등록 명령으로 변경하지 않는다.

### 대안과 ABox 의미

- 단일 boolean 확장: 선택 구성과 승인 범위를 잃으므로 배제했다.
- 등록 때 기존 BOM 객체/관계를 복제: 원본은 이미 조회 자료로 존재하므로 중복과 잘못된 신규 생성 주장을 만들 수 있어 배제했다.
- 모든 source 행마다 승인 링크 추가: 같은 원본 해시와 구성 범위로 충분하며 전체 행 수만큼 불필요한 관계가 늘어나므로 선택하지 않았다.
- 선택한 방식: 반영 시 구성 속성을 갱신하고 `BOM-REG-{draftId}` 등록 기록1개, 해당 `SRC-*` 원본 문서 객체1개, 명명된 `flow` 관계3개를 추가한다. 원본 문서는 파일 카탈로그에 기존 존재하던 자료를 ABox에서 명시 연결한 것이며 새 파일 확보가 아니다. 기록→구성은 등록 반영 대상, 기록→문서는 정확 원본 근거, 문서→구성은 원본 연결이다. 기존 설계/장착/예약 관계를 변경하지 않는다.

QueryPort·GraphPort·Inspector·ABox 다운로드·별도 그래프가 같은 현재 객체/관계 집합을 사용한다. 별도 서버 DTO와 서버 구현은 그대로이며 기존 entities/properties/relations에 읽기 사본을 전달한다. 운영 TBox 클래스/관계·SHACL 정의를 자동으로 바꾸지 않는다. 브라우저 반영 완료와 별도 그래프 갱신 완료는 기존처럼 버전/게시 순서로 구분한다.

### 호환과 제한

기존 내용/해시를 보존하기 위해 정확한 L1 원본 해시와 근거가 있는 구형 payload는 그대로 해석한다. 근거 없는 구형 초안은 읽을 수 있지만 새 원본 접수·초안이 필요하다. boolean-only L1 이력에서 승인자/해시/출처를 추정하지 않으며 상세 연결 미확인으로 표시한다. L1 이외 반영은 기존 `bomApplied`를 변경하지 않는다. 이미 반영한 동일 고정 스냅샷은 추가 등록을 막고 기존 기록 또는 같은 요청 재확인으로 연결한다. 원문 정정·새 개정·승인 취소는 이번에 임의 정책으로 만들지 않는다.

각 구성의 반영은 기존 전역 데이터 버전을 증가시킨다. 다른 초안은 오래된 기준이 되어 재검토가 필요할 수 있다. 계정 전환 시 별도 그래프 세션을 폐기하는 기존 정책도 유지하므로 Bob 전환 뒤 다시 연결한다. 실제 다중 사용자 실시간 공동 편집은 구현하지 않았다.

### 검증과 복구

이번 수행 결과와 중간 실패/재검은 앱 `docs/VALIDATION.md`의 가장 위 후속 절에 기록한다. 단위 표 기반 검사로 5개 원본 바인딩·승인/반영·다른 구성 격리·수량 불변·새2객체/3관계·같은 요청·회사 범위를 확인한다. 실제 Chrome에서 5개 전체 클릭 경로와 별도 그래프의 승인 전/반영 지연/갱신 완료를 확인한다. 자료·이미지·원본 해시는 변경하지 않는다.

복구는 이번 커밋을 되돌리고 원본 브라우저 상태를 내보낸 후 이전 ZIP/소스로 돌아가는 방식이다. 이전 코드에서 새 등록 기록을 읽지 못할 수 있으므로 로컬 기록을 초기화하거나 임의 축약하지 않는다. 최신 ZIP은 source와 lock을 포함하고 과거 검사 기록을 보존한다. PR 자동 병합·운영 배포는 하지 않는다.
