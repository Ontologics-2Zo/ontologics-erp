# ADR-0001 — UI v2.6의 Git 기준 소스 반입

날짜: 2026-11-06 · 상태: 채택 · 범위: UI v2.6 소스 반입과 재현 검증

## 문제와 확인한 사실

첨부 전달 과정의 32MiB 제한 때문에 전체 ZIP에 의존한 개발 인계가 불가능했다. GitHub 저장소는 공개 상태이며 커밋·브랜치가 없는 빈 저장소였다. Work 원본과 `ontologics-ui-redesign-v2.6.zip`에서 의존성·생성 결과물을 제외한 149개 파일의 해시가 일치했다. 이 파일들의 총량은 46,442,997 bytes이며 최대 단일 파일은 1,925,387 bytes다.

원본은 별도 위치에 보존하고 새 작업 폴더에서 검증했다. 기존 실행 중인 업무 화면과 그래프 서버도 중지하거나 변경하지 않았다. v1.7 설계 패키지는 이 반입에 포함되지 않는다.

## 대안과 선택

- 전체 ZIP을 Git에 추가: 중복 생성 결과물까지 포함하고 코드 변경 검토가 어려우므로 채택하지 않았다.
- 기존 원본을 직접 Git 작업 공간으로 사용: 원본 보존 요구와 충돌할 수 있어 채택하지 않았다.
- 필요한 파일을 복사해 별도 브랜치로 반입: 원본 해시를 보존하고 소스 단위 검토·재현이 가능하므로 채택했다.

빈 저장소에는 README만 담긴 최초 `main` 커밋 `2abf33c45cc2d0b82a03ace692df04101e2a4502`를 만들었다. UI 소스는 이 커밋에서 분기한 `import/ui-v2.6`에만 추가하고 PR로 검토한다. 자동 병합과 배포는 수행하지 않는다. 앱 경로는 기존 이름인 `ontologics-prototype/`를 유지한다.

## 반입 조정과 근거

149개 후보 중 142개는 바이트 그대로 포함했다. 기존 파일의 조정은 다음 3개뿐이며 앱 코드와 기존 테스트·의존성 lockfile은 그대로다.

1. `.gitignore`: 생성 결과물·비밀 설정·로컬 도구 정보·참고 사진 제외 규칙 추가.
2. `package.json`: 의존성 변경 없이 `assets:fetch` 명령만 추가.
3. `docs/MEDIA_GENERATION_PROMPTS.json`: 28개 `original` 필드의 개인 절대 경로를 원본 이미지 파일명으로 축소. 프롬프트·자산 ID·대상 파일은 보존.

나머지 4개 제조사 사진은 기존 `docs/MEDIA_ASSET_AUDIT.md`에 재배포 라이선스 미확인·로컬 참고용으로 기록되어 있어 공개 Git 이력에서 제외했다. 대신 공식 HTTPS URL·정확한 크기·SHA-256을 기록하고 명시적인 로컬 복원 명령을 추가했다. 복원은 외부 네트워크와 제조사 파일의 지속적 제공에 의존하며, 출처 파일이 바뀌면 검증 오류를 내고 다른 바이트를 수용하지 않는다. 원본 사진은 별도로 보존되어 있다. 기존 파일이 다르면 덮어쓰지 않는다.

개발 명령과 환경을 설명하는 루트 README, AGENTS.md, `.nvmrc`, 출처 고지와 반입 명세를 추가했다. `.gitattributes`로 자동 줄바꿈 변환을 끄고 기존 CSV의 CRLF를 포함한 원본 바이트를 보존한다. `DELIVERY.json`과 `SOURCE_MANIFEST.json` 등 기존 납품 기록은 수정하지 않았으며, 원본 149개 파일의 반입 여부와 해시는 `docs/UI_V2.6_IMPORT.json`으로 구분한다.

## 검증 결과

검증 환경: macOS arm64, Node.js 22.13.0, npm 10.9.2. 잠금 파일 기반 새 설치를 수행했다. 기본 셸이 Node 20을 선택한 첫 설치에서 엔진 경고가 있어 Node 22.13.0을 명시하여 다시 설치했으며 잠금 파일 변경은 없다. `recharts@2.15.4`의 upstream deprecated 경고는 남아 있으며 이번 소스 반입에서 의존성을 업그레이드하지 않았다.

| 검증 | 결과 |
|---|---|
| `npm ci --no-audit --no-fund` | Node 22.13.0에서 완료 |
| `npm run build` | TypeScript 검사와 Vite 빌드 통과 |
| `npm test` | 4개 파일, 72개 테스트 통과 |
| `npm run test:graph` | 6개 테스트 통과 |
| 기존 전체 브라우저 테스트 | 54개 모두 통과, 실패·건너뜀·불안정 0, 약 165초 |
| 사진 네트워크 복원 | 빈 임시 폴더에서 4개 공식 파일 다운로드, 크기·SHA-256 모두 일치 |
| 복원 보존·거부 조건 | 기존 동일 파일 보존, 다른 파일 보존 후 오류, 비허용 URL 거부 확인 |
| 원본 보존 | 반입 대상 원본 149개 SHA-256 불변 확인 |

Git 인덱스의 반입 파일 145개도 명세의 SHA-256과 대조했다. CSV의 CRLF를 허용한 `git -c core.whitespace=blank-at-eol,blank-at-eof,space-before-tab,cr-at-eol diff --cached --check`에서 기존 공백 경고 2건(`src/ontology-workspace.tsx`의 마지막 빈 줄, `tests/product-grid.e2e.ts`의 후행 공백)이 남았다. 원본 바이트 보존을 위해 수정하지 않았다.

그래프 단위 테스트는 처음 로컬 포트 개방이 제한된 실행 환경에서 `EPERM`으로 실패했다. 포트 개방이 허용된 환경에서 같은 테스트를 다시 실행해 6개 모두 통과했다. 이는 앱 코드 수정으로 해결한 실패가 아니다.

브라우저 검증은 기존 5175/5176 서버를 보호하기 위해 복사본 업무 서버 5177, 복사본 그래프 서버 5186을 사용했다. 임시 테스트 전용 프록시가 브라우저의 5176 요청을 5186으로 전달하며 실제 응답의 upstream 포트를 확인했다. 임시 설정·프록시는 생성 결과물 디렉터리에만 두고 Git에는 포함하지 않는다. 일반 재현 절차는 루트 README의 5175/5176 포트를 사용한다.

이번 검증은 기존 프론트엔드와 로컬 그래프 읽기 모델에 관한 것이다. 실제 ERP 서버 인증·업무 DB·외부 LLM·Docker 격리·운영 배포 및 v1.7 전체 요구사항 수용을 검증한 결과가 아니다. 패키지 취약점 전체 감사는 이 반입 범위에 포함하지 않는다.

## 복구와 후속 작업

PR이 병합되지 않는 한 `main`에는 초기 안내 파일만 남는다. 반입을 취소하려면 PR을 닫으면 되고 원본은 영향을 받지 않는다. 병합 후 되돌릴 때는 기록을 강제로 재작성하지 않고 반입 커밋의 revert PR을 사용한다.

v1.7 패키지를 받으면 별도 변경으로 실제 내용과 버전을 확인한다. 후속 개발은 검증한 커밋 SHA를 명시해 시작하며 UI의 Mock·실제 구현·미검증 범위를 계속 구분한다.
